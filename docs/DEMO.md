# Демо на защите: 5 минут

Организаторы ждут живую работу продукта, а не слайды, и могут попросить показать любой из четырёх
сценариев (см. раздел «Если попросят»). План ниже повторяет тайминг из ТЗ: 1 + 2 + 1 + 1 минута.

## Перед выступлением (за 10 минут)

- [ ] Сервер запущен: `.venv/Scripts/python -m uvicorn cqa.api:create_app --factory --port 8000`,
      http://localhost:8000/ открывается.
- [ ] В шапке выбран «Администратор системы», язык RU, тема тёмная, масштаб браузера 100–110 %.
- [ ] Основной диалог для показа — `p1-ru-001`, по нему ещё нет апелляций. Это единственный диалог
      демо-оператора Алины, поэтому **репетируйте на копии базы**, а не на рабочей: иначе на защите
      апелляция уже будет подана, а в чек-листе останутся пробные изменения (и на контроле их подхватит оценка).

      ```bash
      mkdir -p demo-data && cp data/cqa.sqlite3 data/DEV.json demo-data/
      ```
      ```bash
      CQA_DATA_DIR=demo-data .venv/Scripts/python -m uvicorn cqa.api:create_app --factory --port 8001
      ```
      Репетиция — на http://localhost:8001/, рабочая база (порт 8000) остаётся нетронутой.
      Прогон 08.11 на копии: все шаги сценария работают.
- [ ] Файл для живого прогона под рукой: `docs/demo/new-chat.json`. Ожидаемый результат (проверено 08.11):
      итог 95,5; «Управление диалогом» — 7 из 10 за ожидание почти 5 минут без предупреждения, остальное
      выполнено. Если этот файл уже загружали на репетиции, поменяйте в нём `conversation_id`, чтобы
      карточка открылась без прошлой истории оценок.
- [ ] Интернет есть: оценка идёт через API DeepSeek.

## Сценарий

**0:00–1:00 · Интерфейс и диалог.**
Дашборд: средний балл, соблюдение каждого критерия и «сколько баллов даст исправление», грубые ошибки.
→ «Диалоги»: фильтры по линии, каналу и статусу → открыть `p1-ru-001`.
> «Это рабочее место контроля качества. Чек-лист применяется к чатам и звонкам на трёх языках,
> оценку делает модель, а баллы считает код по правилам чек-листа — итог воспроизводим».

**1:00–3:00 · Оценка, обоснование, переход к реплике, N/A, итог.**
- Итог 92,31 и секции. Раскрыть «Корректная и полная консультация»: ответ 20, объяснение,
  кнопка «реплика 10» → диалог раскрывается и подсвечивает реплику.
- Раскрыть «Выявление потребности» — **N/A**: причина и «Вес 15 распределён между остальными
  критериями». Здесь видно, почему итог не 100: «Завершение» — Нет.
- «Как модель проверяла»: ответы по подпунктам. Внизу журнал: промпт, ответ модели, токены, время.

**3:00–4:00 · Апелляция и решение.**
- В шапке переключиться на «Оператор · Алина» → тот же диалог → «Завершение» → «Оспорить»:
  «Пожелал хорошего вечера — это вежливое завершение» → «Отправить проверяющему».
- Переключиться на «Проверяющий» → «Апелляции»: спорная оценка, комментарий, фрагмент диалога.
  По желанию «Второе мнение ИИ» (≈ 15 с): на репетиции модель ответила «оставляет исходную оценку» —
  хороший момент сказать «ИИ советует, решает человек».
- «Новая оценка» → «Да», причина → «Изменить оценку»: уведомление «Итог: 92.31 → 100». Карточка
  диалога открывается сразу на «После апелляции» (+7,69), по кнопке «Исходная» — ответ модели.

**4:00–5:00 · Изменение чек-листа и применение.**
- «Администратор» → «Чек-лист» → у «Завершения» поменять вес 5 → 10 → «Сохранить версию» →
  «Применить к диалогам» → «Только пересчитать итог (без модели)»: итоги обновились за секунды.
- Если есть время — «Создать с помощью ИИ»: название «Рассказать про промо», описание, вес 5 →
  модель предлагает тип, шкалу, правило N/A и подпункты → «Сохранить версию» → «Применить».
  Решения проверяющих при этом сохраняются.

## Заготовки ответов

**«Почему при повторном прогоне ответ отличается от файла?»** Языковая модель недетерминирована
даже при температуре 0: на DEV между двумя прогонами точность менялась на 3–4 пункта. Поэтому
ответы с расхождениями помечаются «требует проверки», а последнее слово за проверяющим через
апелляцию. Баллы из ответов при этом считаются строго одинаково.

**«Какая модель и сколько стоит?»** DeepSeek V4.1 Flash через внешний API, ≈ $0,007 за оценку
диалога, ≈ 24 с. Более дорогую `deepseek-v4-pro` мы сравнили на тестовых чатах: точнее она не
стала, а работала вчетверо дольше, поэтому оставили Flash. Провайдер заменяемый: Gemini подключён
тем же интерфейсом.

**«Как получена точность?»** Своя разметка DEV, разбитая на `tune` (подбор правил) и `test`
(проверка): на `test` по чатам ≈ 93 %. Разметка черновая, поэтому мы честно называем цифру ориентиром
и сделали лист слепой проверки людьми (`scripts/gold.py review`).

**«Что со звонками?»** Тот же чек-лист по транскрипту. В карточке плеер: клик по времени реплики
включает запись с этого места — проверяющий за секунды слушает спорный момент, а не весь звонок.
Отдельное распознавание речи мы не делали: транскрипт выдан, а бизнесу важнее быстрая проверка
человеком.

**«Почему баллы считает код, а не модель?»** Модель отвечает только «Да / Нет / N/A / ступень» с
доказательствами; веса, перераспределение N/A и округление — детерминированный код из чек-листа.
Итог воспроизводим, а при изменении веса пересчитывается без вызова модели.

**«Как встроить в Dynamics 365?»** Чистые HTML, CSS и ES-модули без сборки; компонент монтируется
в `<div data-cqa-app data-api-base="…">`, стили изолированы под `.cqa-app`, оформление страницы-хозяина
не меняется — подходит как HTML web resource.

## Если что-то пошло не так

- **API модели не отвечает:** показываем уже оценённые диалоги — все сценарии, кроме новой оценки,
  работают без модели (апелляция, решение, пересчёт итога, изменение веса).
- **Страница «зависла» после обновления кода:** плашка «Интерфейс обновлён» вверху → нажать.
- **Случайно испортили демо-диалог:** `p1-ru-008` или `p1-ru-011` — тот же сюжет; апелляцию по ним
  подавайте от «Руководитель · линия RU» (у оператора Алины только `p1-ru-001`).
