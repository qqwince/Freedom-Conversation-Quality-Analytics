# Freedom Conversation Quality Analytics (CQA)

Прототип оценки качества диалогов операторов для хакатона Freedom Broker:
настраиваемый чек-лист, автоматическая оценка RU / KZ / EN диалогов с объяснениями
и ссылками на реплики, апелляции и решение проверяющего.

> Статус: этап 1 — конфигурация чек-листа, контракты данных, загрузка набора.

## Структура

```
config/checklist.default.json   исходный чек-лист (8 критериев, веса, шкалы, правила N/A, подпункты проверки)
schemas/                        JSON Schema: чек-лист и ответ модели
docs/PLAN.md                    план работ под критерии отбора
docs/contracts.md               модели данных: Conversation, Evaluation, Appeal, Decision, формула итога
docs/interpretations.md         принятые трактовки спорных мест и вопросы организаторам
scripts/fetch_dataset.py        загрузка и нормализация набора из API организаторов
data/                           загруженные наборы (не коммитятся)
```

## Быстрый старт

Нужен Python 3.10+ (только стандартная библиотека).

1. Создать файл `.env` в корне проекта (не коммитится) со ссылкой API организаторов:
   ```
   CQA_API_URL=<ссылка GET из задания, с group_id=DEV>
   ```
   и загрузить DEV-набор:
   ```bash
   python scripts/fetch_dataset.py
   ```
2. Контрольный набор — тот же адрес с другим `group_id`:
   ```bash
   python scripts/fetch_dataset.py --url "<ссылка>" --group-id <ID>
   ```
3. Если ответ сохранён из браузера в файл:
   ```bash
   python scripts/fetch_dataset.py --file raw.json
   ```

Результат — `data/<group_id>.json`: к каждой реплике добавлены `idx` (номер для ссылок
в обоснованиях) и `offset_sec` (секунды от начала диалога; для звонков — переход в аудио).
Исходные `timestamp` сохраняются.

## Расчёт итога

См. `docs/contracts.md`. «Да» = полный вес, «Нет» = 0, шкала — пропорционально верхней ступени;
веса критериев с N/A перераспределяются пропорционально, максимум 100; итог округляется
до 2 знаков; грубые ошибки отмечаются отдельно и итог не меняют.
