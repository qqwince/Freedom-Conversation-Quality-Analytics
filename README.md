# Freedom Conversation Quality Analytics (CQA)

Прототип оценки качества диалогов операторов для хакатона Freedom Broker:
настраиваемый чек-лист, автоматическая оценка RU / KZ / EN диалогов с объяснениями
и ссылками на реплики, апелляции и решение проверяющего.

> Статус: готовы ядро оценки, расчёт баллов, сервер API, интерфейс (диалоги, карточка,
> апелляции, редактор чек-листа), черновой эталон и замер точности. В работе: точность модели.

## Как устроена оценка

```
диалог → подготовка (номера реплик, системные события, паузы)
       → промпт из чек-листа → Gemini → JSON с ответами, подпунктами, доказательствами
       → проверки кодом (повтор запроса при ошибках) → голосование
       → расчёт баллов кодом → результат с журналом вызовов модели
```

Модель отвечает только на вопросы чек-листа. Баллы, перераспределение N/A и округление
считает код (`backend/cqa/scoring.py`), поэтому итог воспроизводим.

## Структура

```
config/checklist.default.json   исходный чек-лист: критерии, шкалы, правила N/A, подпункты проверки
schemas/                        JSON Schema: чек-лист и ответ модели
docs/PLAN.md                    план работ под критерии отбора
docs/contracts.md               модели данных и формула итога
docs/interpretations.md         принятые трактовки спорных мест и вопросы организаторам
backend/cqa/
  transcript.py                 подготовка диалога: системные события, паузы, формат для промпта
  prompt.py                     промпт из чек-листа (новый критерий попадает в промпт без правки кода)
  llm/                          провайдеры моделей (Gemini) за общим интерфейсом
  validation.py                 проверка ответа модели по чек-листу и транскрипту
  evaluator.py                  оценка целиком: повторы, голосование, итог, журнал
  scoring.py                    расчёт баллов
  dataset.py                    загрузка и нормализация наборов из API организаторов
  storage.py                    SQLite: диалоги, версии чек-листов, оценки, апелляции
  service.py                    оценка и переоценка, апелляции, фоновые задачи, проверка чек-листа
  api.py                        HTTP API (FastAPI) и раздача интерфейса
  metrics.py                    сравнение с эталоном: точность, ошибка итога, матрицы ошибок
eval/gold/DEV.json              эталонная разметка DEV
scripts/gold.py, scripts/eval.py  эталон и замер точности
scripts/import_run.py           загрузка результатов прогона в базу интерфейса
frontend/                       интерфейс: index.html, css/tokens.css, css/app.css, js/ (api, views)
backend/tests/                  тесты (pytest)
scripts/fetch_dataset.py        загрузка набора из API организаторов
scripts/evaluate.py             пакетная оценка из командной строки
data/, eval/runs/               загруженные наборы и результаты прогонов (не коммитятся)
```

## Быстрый старт

Нужен Python 3.11+.

```bash
python -m venv .venv
```
```bash
.venv/Scripts/python -m pip install -e ".[dev]"
```

Скопируйте `.env.example` в `.env` и заполните `CQA_API_URL` (ссылка GET из задания)
и `GEMINI_API_KEY` (aistudio.google.com → Get API key).

Загрузить DEV-набор:
```bash
.venv/Scripts/python scripts/fetch_dataset.py
```

Контрольный набор — тот же адрес с другим `group_id`:
```bash
.venv/Scripts/python scripts/fetch_dataset.py --group-id <ID>
```

Оценить диалоги:
```bash
.venv/Scripts/python scripts/evaluate.py --ids p1-ru-001 p1-kz-001
```
```bash
.venv/Scripts/python scripts/evaluate.py --lang KZ --limit 5 --votes 3
```

Результаты: `eval/runs/<run_id>/<conversation_id>.json` — ответы, баллы, объяснения,
доказательства, пометки «требует проверки» и журнал вызовов модели.

## Интерфейс

После запуска сервера интерфейс открывается на http://localhost:8000/.

| Раздел | Что делает |
|---|---|
| Диалоги | список с фильтрами (язык, канал, «требуют проверки», «грубая ошибка»), загрузка набора по `group_id` и своего транскрипта, пакетная оценка с прогрессом |
| Карточка диалога | итог и секции, критерии с ответом, баллами и весом; объяснение, доказательства и проверенный участок; клик по доказательству раскрывает диалог и подсвечивает реплику; у звонков — плеер с переходом к моменту реплики; апелляция по критерию; «Исходная / После апелляции»; журнал вызовов модели |
| Апелляции | очередь проверяющего: спорная оценка, комментарий, обоснование модели и фрагмент диалога; «Подтвердить» или «Изменить» с обязательной причиной |
| Чек-лист | редактор критериев (тип, вес, шкала, N/A, подпункты для модели), версии; «Применить к диалогам» переоценивает моделью только изменённые по смыслу критерии, а при смене веса пересчитывает итог без модели |

Результаты прогона из командной строки можно показать в интерфейсе:
```bash
.venv/Scripts/python scripts/import_run.py eval/runs/<run_id>
```

**Встраивание в Dynamics 365.** Интерфейс — чистые HTML, CSS и ES-модули без сборки (`frontend/`).
Компонент монтируется в элемент `<div data-cqa-app data-api-base="https://…">`: в `data-api-base`
указывается адрес сервера оценки. Все стили изолированы под классом `.cqa-app`, цвета и шрифты —
переменные в `css/tokens.css`, маршруты — по `#hash`, поэтому страницу можно загрузить как HTML web resource.

## Сервер API

```bash
.venv/Scripts/python -m uvicorn cqa.api:create_app --factory --port 8000
```

Документация API: http://localhost:8000/docs. При первом запуске в базу (`data/cqa.sqlite3`)
загружаются исходный чек-лист и DEV-набор, если он уже скачан.

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/datasets/import` | загрузить набор по `group_id` из API организаторов |
| POST | `/api/conversations/upload` | загрузить свой транскрипт (запись или ответ API) |
| GET | `/api/conversations` | список диалогов с последней оценкой, фильтры `dataset`, `language`, `channel` |
| GET | `/api/conversations/{id}/audio` | переход к записи звонка (свежая ссылка на mp3) |
| GET/PUT | `/api/checklists/{id}` | чек-лист; сохранение создаёт новую версию |
| POST | `/api/evaluations` | пакетная оценка в фоне; `criteria_ids` — переоценить только эти критерии |
| GET | `/api/jobs/{id}` | прогресс пакетной оценки |
| GET | `/api/evaluations/{id}` | результат; `?include_log=true` — с промптом и ответами модели |
| POST | `/api/evaluations/{id}/appeals` | подать апелляцию по критерию |
| GET | `/api/appeals?status=open` | очередь проверяющего: спорная оценка и комментарий |
| POST | `/api/appeals/{id}/decision` | подтвердить или изменить оценку с причиной |
| GET | `/api/evaluations/{id}/final` | исходная оценка, решения и финальный итог |

## Эталон и замер точности

```bash
.venv/Scripts/python scripts/gold.py status
```
```bash
.venv/Scripts/python scripts/eval.py --split tune --status draft --errors
```

`eval/gold/DEV.json` — наша эталонная разметка DEV: ответы по критериям, заметки к спорным
случаям, статус (`draft` — черновик, `verified` — проверено человеком) и часть `tune`/`test`.
На `test` (19 диалогов) промпт не подгоняется — это честная оценка точности.

## Модель и стоимость

По умолчанию `gemini-3.5-flash`, при перегрузке — запасные модели из `CQA_LLM_FALLBACK_MODELS`.
Один диалог: ~4–5 тыс. входных и ~3–7 тыс. выходных токенов на один вызов (выход включает
рассуждения модели). Итоговая модель и стоимость оценки будут указаны после замера точности.
